# Угадай число — SOLID

ДЗ по SOLID. Сделал консольную игру на C#: программа загадывает число, игрок вводит варианты и получает подсказки «больше» или «меньше».

## Как запустить

Нужен .NET SDK 9.0. Из папки проекта:

```powershell
dotnet run --project src/GuessNumber -c Release
```

Можно также открыть `OtusSolid.sln` в Visual Studio и выбрать `GuessNumber` стартовым проектом.

Диапазон и количество попыток меняются в `src/GuessNumber/settings.json`:

```json
{
  "MinNumber": 1,
  "MaxNumber": 100,
  "MaxAttempts": 7
}
```

Обе границы входят в диапазон. Можно задать отрицательные числа или диапазон из одного числа. Попыток должно быть больше нуля.

При запуске файл копируется к программе. Можно передать и другой файл настроек:

```powershell
dotnet run --project src/GuessNumber -c Release -- "D:\otus_dz\otus-solid\src\GuessNumber\settings.json"
```

Если вместо числа ввести текст или число вне диапазона, попытка не тратится. При завершении ввода игра останавливается. Если попытки закончились, выводится правильный ответ.

## Что сделал по SOLID

### S — единственная ответственность

Разделил код по задачам. `GuessNumberGame` отвечает за ход игры: попытки, сравнение и результат. `RandomSecretNumberGenerator` выбирает число. `JsonGameSettingsProvider` читает настройки из файла, а `GameSettings` хранит их и проверяет допустимые значения. `ConsoleGameInput` и `ConsoleGameOutput` работают с консолью.

Например, при изменении формата настроек не нужно менять правила игры. Все зависимости собираются в `Program.cs`.

### O — открытость/закрытость

Игра принимает `ISecretNumberGenerator`, поэтому можно добавить другой способ выбора числа, не редактируя `GuessNumberGame`. В проверках добавил `MidpointSecretNumberGenerator`: он выбирает середину диапазона. С ним используется тот же код игры.

Для другого способа ввода или вывода тоже достаточно новой реализации соответствующего интерфейса. Для настроек есть `IGameSettingsProvider`: вместо JSON можно добавить другой источник, поменяв подключение в `Program.cs`.

### L — подстановка Барбары Лисков

У `ISecretNumberGenerator` есть общий контракт: для корректного диапазона вернуть число внутри него, включая границы. Диапазон из одного числа тоже допустим. Случайный генератор и генератор середины соблюдают эти условия, не требуют дополнительных ограничений от игры.

Оба генератора проверяются одинаковыми проверками: положительный и отрицательный диапазон, одно число, крайние значения `int`. Есть и проверка самой игры с каждым генератором: перебор всего маленького диапазона должен приводить к победе независимо от способа выбора числа.

### I — разделение интерфейсов

Не стал делать один большой интерфейс для консоли, настроек и генерации. Выделил небольшие интерфейсы: `IGameInput`, `IGameOutput`, `ISecretNumberGenerator`, `IGameSettingsProvider`. У каждого один метод.

Ввод и вывод разделены. Поэтому `ScriptedInput` в проверках только отдаёт строки, а `RecordingOutput` только записывает сообщения. Им не приходится реализовывать ненужные методы или бросать `NotImplementedException`.

### D — инверсия зависимостей

`GuessNumberGame` зависит от интерфейсов, которые получает через конструктор. В нём нет вызовов `Console`, чтения файлов или создания `Random`.

Конкретные реализации выбираются в `Program.cs`. В проверках вместо консоли подставляются подготовленные строки и сборщик сообщений. Контейнер внедрения зависимостей для такого проекта не понадобился.

## Проверки

Сделал отдельную консольную программу с проверками, без сторонних пакетов:

```powershell
dotnet run --project tests/GuessNumber.Checks -c Release
```

Проверяются победа на последней попытке, обе подсказки, проигрыш и лимит попыток, неверный ввод, завершение ввода, настройки и замена генераторов. Ожидаемый итог: `Пройдено: 8/8`. При провале есть сообщение об ошибке и код завершения 1. Запускать нужно через `dotnet run`, это не проект для `dotnet test`.

Сборка всего решения:

```powershell
dotnet build OtusSolid.sln -c Release
```
